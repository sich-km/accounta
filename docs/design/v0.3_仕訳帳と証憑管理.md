# Accounta v0.3 仕訳帳・証憑管理 詳細設計書

この文書は、[Accounta要求仕様書](../../SPEC.md)のv0.3で追加する簡易的な仕訳帳と証憑管理の詳細設計を定義する。

v0.2までの機能、権限、Organization単位のデータ分離およびExcel出力を維持し、複式簿記による仕訳登録に必要な最小機能だけを追加する。実装時は既存コードの規約を優先し、この文書と要求仕様書が矛盾する場合は要求仕様書を最上位とする。

---

# 1. 対象範囲

v0.3で実装する機能:

- 仕訳用勘定科目マスタの一覧、登録、編集および有効・無効管理
- 仕訳の一覧、詳細、登録、編集および削除
- 1仕訳に対する複数の借方・貸方明細
- 借方合計と貸方合計の一致Validation
- 仕訳明細単位の任意の部門設定
- 仕訳への証憑ファイル添付、確認、ダウンロードおよび紐付け解除
- Organization単位のデータ分離
- ダッシュボードとメニューへの仕訳機能追加
- 通常のExcelエクスポートへの仕訳帳Sheet追加
- 仕訳、証憑および仕訳用勘定科目に関するFeature Test

v0.3では次を実装しない:

- 仕訳の承認、確定、締め、取消および訂正履歴
- 定型仕訳、複合仕訳テンプレートおよび自動仕訳
- 固定資産からの減価償却仕訳生成
- 予実管理科目と仕訳用勘定科目のマッピング
- 仕訳実績から予実管理実績への自動反映
- 開始残高、決算整理、決算振替および翌期繰越の専用処理
- 消費税区分、税率、課税区分および税額計算
- 補助科目、取引先、プロジェクトおよびセグメント
- 外貨、為替換算および外貨建金額
- 証憑のOCR、内容解析、重複判定および仕訳候補生成
- 総勘定元帳、残高試算表、P/LおよびB/S

# 2. 設計方針

## 2.1 仕訳の単位

- 1つの仕訳を1件の `journal_entries` レコードとして保存する
- 借方・貸方の各行を `journal_entry_lines` に保存する
- 仕訳は2行以上の明細を持ち、借方と貸方を最低1行ずつ含む
- 借方合計と貸方合計が一致した仕訳だけを保存する
- 保存済み仕訳は下書き状態を持たず、有効な会計データとして扱う
- 仕訳番号専用Columnは設けず、Organization内で参照可能な仕訳IDを画面上の識別子として表示する

## 2.2 仕訳用勘定科目

- 仕訳用勘定科目は `ledger_accounts` Tableで管理する
- 予実管理用の `management_accounts` とは別Table・別Modelとし、自動同期しない
- 勘定科目区分は資産、負債、純資産、収益および費用とする
- 通常残高は借方または貸方として明示的に保持する
- 通常残高は入力支援と将来の残高計算に利用するが、仕訳入力時の借方・貸方を強制しない
- 利用済み勘定科目は物理削除せず、無効化して履歴を維持する
- DBには文字列コードを保存し、アプリケーションではPHP backed enumで管理する

## 2.3 部門

- 仕訳情報にその仕訳を起票・管理する起票部門を任意保持する
- 新規登録時の起票部門の初期値はログインユーザーの所属部門とする
- 編集時は保存済みの起票部門を表示し、仕訳明細から推測・再構成しない
- 起票部門は新しく追加する明細の個別部門の初期値に使用する
- 起票部門を変更しても、既存明細の個別部門は上書きしない
- 仕訳明細ごとに個別部門を任意設定でき、起票部門と異なる部門や未設定も許可する
- 売上や費用等、部門管理が必要な明細だけに部門を設定できる
- 現金、借入金等の部門を必要としない明細は未設定を許可する
- 新規登録では同一Organizationの有効な部門だけを選択できる
- 編集では既存明細に設定済みの無効な部門を維持できる

## 2.4 金額

- 金額は符号なしの正数として保存し、借方・貸方は `side` で区別する
- 0円、負数および小数第3位以下を持つ金額は保存しない
- 合計比較では浮動小数点数を使用せず、正規化した小数文字列を最小通貨単位へ変換して比較する
- v0.3では通貨を日本円に限定し、金額Columnは既存機能と同じく小数2桁を保持する

## 2.5 証憑

- 1つの仕訳へ複数の証憑ファイルを添付できる
- 1つの証憑ファイルは1つの仕訳だけに所属する
- 証憑はWeb公開ディレクトリへ保存せず、Laravel Storageの非公開Diskへ保存する
- ファイル確認とダウンロードは認可済みControllerを経由する
- DBへ保存するPathはサーバー側で生成し、利用者が保存先Pathを指定できないようにする
- 紐付け解除時はDBレコードと保存ファイルを削除する
- 仕訳削除時は紐付く証憑ファイルも削除する

# 3. 権限制御

## 3.1 仕訳用勘定科目

| 操作 | `admin` | `company_admin` | `user` |
| --- | --- | --- | --- |
| 一覧表示 | 可 | 可 | 可 |
| 登録 | 可 | 可 | 不可 |
| 編集 | 可 | 可 | 不可 |
| 有効・無効変更 | 可 | 可 | 不可 |

仕訳用勘定科目マスタの導線は通常ナビゲーションの「管理」から開く管理トップ画面に配置し、`admin` と `company_admin` だけに表示する。一般ユーザーは仕訳入力時の選択肢として有効な勘定科目を利用できる。

## 3.2 仕訳・証憑

| 操作 | `admin` | `company_admin` | `user` |
| --- | --- | --- | --- |
| 仕訳一覧・詳細 | 可 | 可 | 可 |
| 仕訳登録・編集・削除 | 可 | 可 | 可 |
| 証憑添付・確認・解除 | 可 | 可 | 可 |
| Excel出力 | 可 | 可 | 可 |

- すべての操作は認証を必須とする
- ログインユーザー自身のOrganizationに属するデータだけを利用できる
- URLへ他OrganizationのIDを指定した場合は `404 Not Found` とし、存在を開示しない
- Requestの `organization_id` は受け付けず、ログインユーザーのOrganizationからサーバー側で設定する
- 証憑の親仕訳と証憑自身のOrganizationを両方確認する

# 4. 画面設計

## 4.1 画面一覧

| 画面 | Route名 | 主な用途 |
| --- | --- | --- |
| 仕訳帳 | `journal-entries.index` | 所属Organizationの仕訳を確認する |
| 仕訳登録 | `journal-entries.create` | 複数明細を持つ仕訳を登録する |
| 仕訳詳細 | `journal-entries.show` | 仕訳、貸借合計および証憑を確認する |
| 仕訳編集 | `journal-entries.edit` | 仕訳ヘッダーと明細を更新する |
| 管理トップ | `management.index` | 権限者が各種マスタ管理画面を選択する |
| 仕訳用勘定科目一覧 | `ledger-accounts.index` | 仕訳用勘定科目を確認・管理する |
| 仕訳用勘定科目登録 | `ledger-accounts.create` | 仕訳用勘定科目を登録する |
| 仕訳用勘定科目編集 | `ledger-accounts.edit` | 仕訳用勘定科目を編集する |

通常ナビゲーションとダッシュボードの業務メニューへ「仕訳帳」を追加する。通常ナビゲーションは「仕訳帳」「固定資産管理台帳」「予算・実績」の順とし、権限者にはその後ろに管理トップ画面へ遷移する「管理」を表示する。「管理」はドロップダウンにせず、管理トップ画面に部門マスタ、予実管理科目マスタ、仕訳用勘定科目マスタおよび権限に応じた会社情報管理へのカードを配置する。各管理画面には管理トップまたは直前の一覧へ戻る導線を表示する。

## 4.2 仕訳一覧

- 1ページ20件でページネーションする
- 仕訳日降順、同一日の場合はID降順で表示する
- 次の項目を表示する
  - 仕訳ID
  - 仕訳日
  - 摘要
  - 借方合計
  - 貸方合計
  - 明細数
  - 証憑数
  - 詳細・編集・削除操作
- 金額は3桁区切り、小数2桁で表示する
- 一覧の検索、期間絞り込みおよび勘定科目絞り込みはv0.5で追加する
- 詳細・編集・削除は三点リーダーの操作メニューへまとめる
- 操作メニューは表のスクロール領域外へ描画し、表の横スクロールや表示領域によって切れないようにする
- 削除は確認Modalを経由する

## 4.3 仕訳登録・編集

ヘッダー入力項目:

1. 仕訳日
2. 起票部門
3. 摘要
4. 備考

明細入力項目:

1. 借方・貸方
2. 仕訳用勘定科目
3. 部門
4. 金額
5. 明細摘要

- 初期表示では明細を用意せず、「仕訳入力」操作で借方1行と貸方1行を追加する
- 以降は借方・貸方ごとの追加操作で明細を1行ずつ追加する
- 新規明細の個別部門には、追加した時点の起票部門を設定する
- 日付と勘定科目が選択され、明細摘要が未入力の場合は「YYYY年M月の勘定科目名」を入力候補として表示する
- Alpine.jsを利用して明細行の追加・削除を行う
- 画面上で借方合計、貸方合計および差額を表示する
- JavaScriptによる合計表示は入力支援とし、保存可否は必ずサーバー側で判定する
- 最低2行を残し、借方または貸方が0行になる削除操作を防ぐ
- 新規登録・編集画面の先頭で任意の証憑ファイルを選択でき、既存分を含めて最大10件まで添付できる
- 新規登録では有効な仕訳用勘定科目と部門だけを選択肢に表示する
- 編集では現在使用中の無効な仕訳用勘定科目と部門を表示・維持できる
- 登録成功後は詳細画面へ遷移する
- 更新成功後は詳細画面へ遷移する
- 入力エラー時は明細行を含む入力内容とエラーを保持する

## 4.4 仕訳詳細・証憑

- ヘッダー、全明細、借方合計および貸方合計を表示する
- 借方明細と貸方明細を判別できる表形式で表示する
- 各明細に勘定科目コード・名称、部門および明細摘要を表示する
- 登録日時と更新日時を表示する
- 証憑一覧に元ファイル名、MIME Type、ファイルサイズおよび登録日時を表示する
- 証憑の追加、確認・ダウンロードおよび紐付け解除を提供する
- 新規登録・編集時は仕訳と同時に複数の証憑を添付できる
- 詳細画面では証憑の追加、確認・ダウンロードおよび紐付け解除を行う

| --- | --- | --- | --- | --- |
| `id` | `id` | No | 自動 | 主キー |
| `organization_id` | `foreignId` | No | なし | 所属Organization |
| `code` | `string(32)` | No | なし | Organization内で一意の科目コード |
| `name` | `string(100)` | No | なし | 仕訳用勘定科目名 |

| Code | 表示名 | 原則的な通常残高 |
| --- | --- | --- |
| `asset` | 資産 | 借方 |
| `liability` | 負債 | 貸方 |
| `equity` | 純資産 | 貸方 |
| `revenue` | 収益 | 貸方 |
| `expense` | 費用 | 借方 |

# 6. 入力Validation

## 6.1 仕訳用勘定科目

| 項目 | Rule |
| --- | --- |
| 科目コード | 必須、文字列、32文字以内、英大文字・数字・`_`・`-`、先頭は英大文字または数字 |
| 科目名 | 必須、文字列、100文字以内 |
| 勘定科目区分 | 必須、定義済みコード |
| 通常残高 | 必須、`debit` または `credit` |

- 科目コードはOrganization内で一意とする
- 科目コードは前後空白を除去して英大文字へ変換する
- 科目名は前後空白を除去する
- 利用済み科目のコード、名称、区分および通常残高は編集できるが、既存仕訳明細は同じ科目IDを参照し続ける

## 6.2 仕訳ヘッダー

| 項目 | Rule |
| --- | --- |
| 仕訳日 | 必須、有効な日付、`1900-01-01`から`9999-12-31` |
| 起票部門 | 任意、整数、同一Organizationの選択可能な部門 |
| 摘要 | 必須、文字列、200文字以内 |
| 備考 | 任意、文字列、500文字以内 |

摘要と備考は前後空白を除去し、空文字の備考はNullとして扱う。

## 6.3 仕訳明細

| 項目 | Rule |
| --- | --- |
| 明細 | 必須、配列、2件以上100件以下 |
| 貸借区分 | 必須、`debit` または `credit` |
| 仕訳用勘定科目 | 必須、整数、同一Organizationの選択可能な科目 |
| 部門 | 任意、整数、同一Organizationの選択可能な部門 |
| 金額 | 必須、0より大きい数値、整数13桁・小数2桁以内 |
| 明細摘要 | 任意、文字列、200文字以内 |

相関Validation:

- 借方明細と貸方明細を最低1件ずつ必要とする
- 借方合計と貸方合計を一致させる
- 新規登録では有効な勘定科目と部門だけを許可する
- 更新では当該仕訳が現在使用している無効な勘定科目と部門に限り維持を許可する
- 新規登録時の空の明細摘要は「YYYY年M月の勘定科目名」で補完して保存する。例: `2026年9月の貸付金`
- 入力済みの明細摘要は自動補完で上書きせず、更新時の空の明細摘要はNullとして扱う
- 配列順を1から始まる `line_number` としてサーバー側で付与し、Requestからの明細番号は信用しない

## 6.4 証憑

| 項目 | Rule |
| --- | --- |
| 証憑ファイル | 新規・編集時の同時添付は任意、個別追加時は必須、File、1件最大10MiB |
| MIME Type | PDF、JPEGまたはPNG |
| 1仕訳の添付数 | 最大10件 |

- MIME Typeは利用者が送信した文字列だけでなく、Uploadされたファイル内容から判定する
- 元ファイル名をStorage Pathとして使用しない
- 同じ元ファイル名の複数添付を許可する
- v0.3ではZIP、Office文書、HEICおよび実行可能ファイルを許可しない

## 7.3 Service・Transaction制御

- 仕訳登録・更新は `JournalEntryService` のDB Transaction内で行う
- 登録時はヘッダーを作成した後、正規化済み明細をRelationから作成する
- 新規登録時に証憑が選択されている場合は、仕訳ヘッダーと明細を保存して仕訳IDを確定した後、そのIDへ証憑を順番に紐付ける
- 同時添付の途中で保存に失敗した場合は、作成した仕訳、明細、証憑DBレコードおよび保存済みファイルを補償削除し、仕訳だけが残る部分成功を防ぐ
- 更新時はヘッダー更新、明細の置換および追加証憑のDB登録を同一Transactionで行う
- 更新時の追加証憑保存に失敗した場合はDB更新をRollbackし、今回保存した証憑ファイルを補償削除する
- 貸借不一致、外部キー違反または保存失敗時はヘッダーと明細をすべてRollbackする
- 仕訳削除時は証憑Pathを取得し、DB削除成功後に物理ファイルを削除する
- 証憑保存後にDB登録が失敗した場合は保存済みファイルを削除する
- 証憑DB削除後の物理ファイル削除失敗は記録し、利用者へ処理失敗を通知する

- 複数借方・複数貸方の複合仕訳を登録できる
- 借方合計と貸方合計が一致しない仕訳を拒否する
- 借方または貸方がない仕訳を拒否する
- 1行だけ、0円、負数、小数第3位以下および100行超の明細を拒否する
- 仕訳と明細が同一Transactionで保存される
- 更新時にヘッダーと全明細を置換できる
- 新規登録の起票部門にユーザーの所属部門が初期表示される

- Guestは仕訳Routeを利用できない
