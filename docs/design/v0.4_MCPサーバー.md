# Accounta v0.4 MCPサーバー 詳細設計書

この文書は、[Accounta要求仕様書](../../SPEC.md)のv0.4で追加するAccounta MCP Serverの詳細設計を定義する。

v0.4の目的は、MCPそのものを理解できる最小構成を入れることである。外部から利用できる業務機能は仕訳帳の参照だけとし、マスタ、予実、固定資産、財務諸表などの参照は後続バージョンで順に足す。

v0.3までの画面機能、権限、Organization単位のデータ分離およびExcel出力は維持する。実装時は既存コードの規約を優先する。Laravel MCPのAPIは、実装時点の公式ドキュメントを確認して使う。

現行実装を正とする。この文書と実装が異なる場合は実装を優先し、文書を更新する。仕訳と証憑の意味は [v0.3 仕訳帳と証憑管理](v0.3_仕訳帳と証憑管理.md) を正とする。

Laravel BoostのMCP Serverは開発支援用であり、Accounta MCP Serverとは別物とする。

---

# 1. 対象範囲

v0.4で実装する機能:

- `laravel/mcp` によるAccounta MCP Server
- CodexおよびCursor向けのローカルプロセス接続（`Mcp::local`）
- 認証付きのローカルHTTP接続（`Mcp::web`）
- 仕訳帳のデータ参照（明細と証憑メタデータを含む）
- Organization単位のデータ分離
- MCP Toolに関するFeature Test

公開する業務Toolは **1つ** とする。名前は `get-journal-entries`。

v0.4では次を実装しない:

- 所属会社・組織・マスタ、予算・実績、固定資産、P/L、B/S、総勘定元帳のMCP参照
- 仕訳、証憑およびその他データの登録・更新・削除
- 任意SQLの実行
- 証憑ファイル本体、保存PathおよびDisk名の公開
- Laravel PassportによるOAuth 2.1
- JetstreamのAPI Token管理画面
- ChatGPT向けトンネル、リモート公開およびホスティングの自動化
- MCP Clientとして他システムのMCP Serverを呼び出す機能
- Prompt、Resource、MCP App

---

# 2. 設計方針

## 2.1 役割

Accounta MCP Serverは、MCP Clientが仕訳帳を自然言語で参照するための最小入口とする。画面と同じEloquent ModelとOrganization Scopeを使い、データベースへ直接SQLを発行する入口は作らない。

## 2.2 接続方式

同じServerクラスを2通りで登録する。

| 方式 | 登録 | 主なClient | 対象組織の識別 |
| --- | --- | --- | --- |
| ローカルプロセス | `Mcp::local('accounta', AccountaServer::class)` | Codex、Cursor | `.env` の `ACCOUNTA_MCP_LOGIN_ID` に対応するUser |
| Web | `Mcp::web('/mcp/accounta', AccountaServer::class)` | ローカルHTTP | Sanctum Bearer TokenのUser |

ローカルプロセスはHTTPを介さない。Webは `auth:sanctum` とMCP用Rate Limitを必須とする。

## 2.3 参照専用

唯一のToolに `#[IsReadOnly]` と `#[IsIdempotent]` を付ける。破壊的更新を行うToolは置かない。Requestから `organization_id` を受け取っても、接続UserのOrganization以外へ切り替えない。

## 2.4 データ範囲

- 返却する仕訳は、接続Userの所属Organizationに限定する
- 他Organizationの仕訳IDを指定した場合は存在を開示せず、見つからない旨を返す
- 一覧の既定件数は50、最大は200とする
- 金額は小数2桁の文字列、日付は `Y-m-d` とする

## 2.5 証憑

仕訳に紐付く証憑はメタデータだけを返す。次は返さない。

- ファイル本体
- Storage Disk名
- 保存Path
- ファイル内容のOCR結果

返す項目は、証憑ID、元ファイル名、MIME Type、ファイルサイズ、登録日時、紐付く仕訳IDに限定する。

## 2.6 Laravel Boostとの分離

Laravel Boostが生成する `laravel-boost` MCP Serverの設定は開発支援用のまま維持し、Accounta MCP Serverの設定で上書きしない。Accounta MCPは別エントリ `accounta` として追加する。

`boost.json` ではCodexとCursorを対象Agentとし、開発時はCodexを主に使用する。Laravel Boostが同期する `AGENTS.md` と `.agents/skills`、およびCodexのプロジェクト設定 `.codex/config.toml` はGit管理し、開発環境間で共有する。`.codex/config.toml` には秘密情報、開発者固有の絶対Pathおよび認証情報を含めない。Cursor固有の `.cursor/mcp.json` は各開発者のローカル設定としてGit管理しない。

# 3. 技術基準

- Laravel 13
- PHP 8.3以上
- パッケージ `laravel/mcp`。インストールは利用者が行う
- 既存の `laravel/sanctum` をWeb認証に使う。Passportは追加しない
- JetstreamのAPI Token画面は有効化しない
- UI Localeは日本語、Timezoneは `Asia/Tokyo` とする
- MCPのTool名は英語、説明文は日本語とする
- 応答は `Response::structured()` を基本とする

# 4. 認証・権限制御

## 4.1 ローカルプロセス

- 接続時のUserは `config('accounta.mcp.login_id')`（環境変数 `ACCOUNTA_MCP_LOGIN_ID`）から解決する
- 該当Userが存在しない、またはOrganizationに所属しない場合はTool実行を拒否する
- ローカルプロセスは開発者のマシン上だけで使う。Tokenは不要とする
- `.env` のログインIDはソースコードへ固定しない

## 4.2 Web

- `auth:sanctum` を必須とする
- 未認証リクエストは拒否する
- Tokenは画面から発行せず、Artisan Command `accounta:mcp-token {login_id}` で発行する
- Tokenの能力は `mcp:read` のみとする
- 発行した平文Tokenは初回だけコンソールへ表示し、ソースコードやSeederへ保存しない
- 失効は `accounta:mcp-token {login_id} --revoke` で行う
- Jetstreamの「API Tokens」メニューは出さない
- User Modelへ `Laravel\Sanctum\HasApiTokens` を追加する。これはMCP用であり、v0.1で無効化した一般向けAPI Token機能を復活させるものではない

## 4.3 権限

`admin`、`company_admin`、`user` のいずれも、自Organizationの仕訳を参照できる。Web Tokenに `mcp:read` 以外の能力しかない場合は拒否する。

## 4.4 Rate Limit

Web MCPは専用Limiter `mcp` を付ける。同一TokenまたはIPあたり1分60回を上限の目安とする。ローカルプロセスにはHTTP Rate Limitを適用しない。

# 5. Server設計

## 5.1 Serverクラス

`app/Mcp/Servers/AccountaServer.php`

- Name: `Accounta`
- Version: `0.4.0`
- Instructions: 参照専用であること、公開Toolは仕訳帳の参照だけであること、対象は接続Userの所属Organizationのみであること、任意SQLはできないこと、証憑はメタデータのみであることを明示する

## 5.2 登録

`routes/ai.php`:

```php
Mcp::local('accounta', AccountaServer::class);

Mcp::web('/mcp/accounta', AccountaServer::class)
    ->middleware(['auth:sanctum', 'throttle:mcp']);
```

Web URIは `/mcp/accounta` で固定する。公開APIとしてのCRUD Routeは追加しない。

## 5.3 起動

| 用途 | コマンド |
| --- | --- |
| ローカルServer | Clientが `php artisan mcp:start accounta` を起動する |
| 動作確認 | `php artisan mcp:inspector accounta` |
| Web確認 | アプリ起動後に `php artisan mcp:inspector mcp/accounta` |

利用者が `mcp:start` を常時手動起動する運用にはしない。CodexやCursorのClient設定に起動コマンドを書く。

# 6. Tool設計

公開Toolは `get-journal-entries` のみとする。`app/Mcp/Tools/GetJournalEntriesTool.php` に置き、`Laravel\Mcp\Server\Tool` を継承する。入力は `schema()` と `$request->validate()` の両方で確認する。Organizationの決定は `App\Mcp\Support\McpContext` に集約する。

## 6.1 `get-journal-entries`

接続Organizationの仕訳帳を参照する。一覧と1件取得を兼ねる。

入力:

| 引数 | 必須 | 内容 |
| --- | --- | --- |
| `year` | 任意 | 会計年度。省略時は当年度 |
| `month` | 任意 | 会計月。`year` が無いときは無視する |
| `journal_entry_id` | 任意 | 指定時はその1件だけを返す |
| `limit` | 任意 | 既定50、最大200。`journal_entry_id` 指定時は無視する |

出力:

- 対象期間
- 件数
- 仕訳の配列。各仕訳は次を含む
  - 仕訳ID、仕訳日、摘要、備考、起票部門コード
  - 借方合計、貸方合計
  - 明細（貸借、科目コード・名称、部門コード、金額、明細摘要）
  - 証憑メタデータ（証憑ID、元ファイル名、MIME Type、ファイルサイズ、登録日時）

並びは仕訳日降順、同一日はID降順。他Organizationの `journal_entry_id` は見つからないとして扱う。

# 7. Application構成

## 7.1 追加File

| File | 責務 |
| --- | --- |
| `routes/ai.php` | Local/Web MCP Serverの登録 |
| `.codex/config.toml` | Codex向けLaravel BoostおよびAccounta MCP Serverの接続設定 |
| `config/accounta.php` | MCP接続UserなどAccounta固有設定 |
| `app/Mcp/Servers/AccountaServer.php` | Server定義とTool登録 |
| `app/Mcp/Support/McpContext.php` | 接続UserとOrganizationの解決 |
| `app/Mcp/Tools/GetJournalEntriesTool.php` | 仕訳帳の参照 |
| `app/Console/Commands/IssueMcpTokenCommand.php` | MCP Tokenの発行と失効 |
| `tests/Feature/Mcp/AccountaServerTest.php` | Server登録、認証、Organization分離、仕訳参照 |

既存の画面ControllerはMCPから呼び出さない。

## 7.2 `McpContext`

- Webでは `$request->user()` を使う
- ローカルプロセスでは `ACCOUNTA_MCP_LOGIN_ID` のUserを使う
- UserもOrganizationも解決できない場合は `Response::error()` で拒否する
- ToolへOrganization IDを引数として公開しない

## 7.3 設定

`config/accounta.php`:

- `mcp.login_id` ← `env('ACCOUNTA_MCP_LOGIN_ID')`
- 空文字は未設定として扱う

`.env.example` へ次を追加する。値は空のままにする。

```
ACCOUNTA_MCP_LOGIN_ID=
```

# 8. Client接続

## 8.1 Codex

プロジェクト共有の `.codex/config.toml` へ `accounta` を追加する。既存の `laravel-boost` エントリは残し、Codexの作業ディレクトリはアプリケーションルートとする。

```toml
[mcp_servers.accounta]
command = "php"
args = ["artisan", "mcp:start", "accounta"]
```

## 8.2 Cursor

ローカルの `.cursor/mcp.json` へ `accounta` を追加する。Laravel Boostが生成した `laravel-boost` エントリは残し、作業ディレクトリはアプリケーションルートとする。

```json
{
    "mcpServers": {
        "laravel-boost": {
            "command": "php",
            "args": ["artisan", "boost:mcp"]
        },
        "accounta": {
            "command": "php",
            "args": ["artisan", "mcp:start", "accounta"]
        }
    }
}
```

`.codex/config.toml` はリポジトリへコミットし、Codexを使用する環境で共有する。`.cursor/mcp.json` は `.gitignore` の対象とし、リポジトリへコミットしない。どちらの設定にもTokenなどの秘密情報を直接記載しない。ローカル接続では `.env` の `ACCOUNTA_MCP_LOGIN_ID` に、参照したいUserの `login_id` を設定する。

## 8.3 ローカルHTTP

アプリを起動したうえで、`POST /mcp/accounta` へ `Authorization: Bearer {token}` を付ける。Tokenは `php artisan accounta:mcp-token {login_id}` で発行する。

ChatGPTやインターネット経由の接続はv0.4の対象外とする。認証なしの公開、データベースポートの公開、TokenのGit管理は禁止する。

---

# 9. セキュリティ

- 任意SQL、Tinker相当の実行、Artisanの任意実行は公開しない
- 書き込みToolを置かない
- 仕訳以外の業務データを返すToolを置かない
- 証憑ファイルをTool応答へ載せない
- Web MCPを認証なしで登録しない
- Token平文をログへ出さない
- `.codex/config.toml` にToken、秘密情報または開発者固有の絶対Pathを記載しない
- 他Organizationの件数やIDをエラーメッセージへ含めない
- `organization_id` をTool引数で受け取っても無視し、接続UserのOrganizationだけを使う

---

# 10. 自動テスト設計

PestのFeature Testとし、Laravel MCPの `AccountaServer::actingAs($user)->tool(...)` を使う。

## 10.1 認証と対象組織

- 認証済みUserの所属Organizationの仕訳を返せる
- 未認証のWeb呼び出しを拒否する
- `ACCOUNTA_MCP_LOGIN_ID` 未設定のローカル解決を拒否する
- 他Organizationの仕訳IDを指定しても仕訳を返さない

## 10.2 参照内容

- 会計年度で仕訳一覧を取得できる
- `journal_entry_id` で1件の明細と証憑メタデータを取得できる
- 証憑応答にPath、Disk、ファイル本体が含まれない
- Serverに登録されている業務Toolが `get-journal-entries` だけである

## 10.3 書き込み禁止

- 登録・更新・削除のToolがServerに存在しない
- 既存の画面CRUD TestがMCP追加後も成功する

---

# 11. 既存機能への影響

- 画面Route、権限、Excel、Seederの業務データは変更しない
- Userへ `HasApiTokens` を追加しても、Jetstream API Token画面は出さない
- `routes/api.php` の `/api/user` は現行どおり残し、MCPの主入口にはしない
- 既存の無効化済み認証機能（パスワードリセット、2FA、Passkeys、アカウント削除）は有効化しない
- Laravel Boostが生成した `laravel-boost` MCP Serverの設定は上書きせず、Accounta用エントリを別に追加する
- `boost.json` ではCodexとCursorを対象Agentとし、`.codex/config.toml` はGit管理する。Cursor固有の `.cursor` はGit管理しない

---

# 12. 実装順序

1. 利用者が `laravel/mcp` をインストールし、`routes/ai.php` をpublishする
2. `config/accounta.php` と `.env.example` を追加する
3. `McpContext` と `AccountaServer` を追加する
4. `GetJournalEntriesTool` とFeature Testを追加する
5. Sanctum Token CommandとWeb登録、Rate Limitを追加する
6. CodexおよびCursor用の接続例をこの文書の通りに確認する
7. PHP CodeをPintで整形する

インストール前にToolクラスを本実装しない。パッケージ導入後に `make:mcp-server` と `make:mcp-tool` で骨格を作る。

# 13. v0.4 完了条件

次をすべて満たした場合にv0.4のMCPサーバーを完了とする。

- Codex、Cursorまたは同等のローカルMCP Clientから、接続Organizationの仕訳帳を参照できる
- 仕訳明細と証憑メタデータを取得できる
- 公開している業務Toolが仕訳帳参照の1つだけである
- 証憑ファイル本体と任意SQLを公開していない
- 書き込みToolが存在しない
- Web接続は認証なしでは利用できない
- 対象Feature Testが成功する
- v0.3までの既存機能が継続して動作する
- 重大な既知不具合がない

ChatGPTからの実接続確認は完了条件に含めない。

# 14. 将来バージョンへ延期する論点

- 所属会社・組織、マスタ、予算・実績、固定資産のMCP参照
- 総勘定元帳、P/L、B/SのMCP参照
- MCPからの登録・更新・削除
- 証憑ファイルの条件付き取得
- PassportによるOAuth 2.1とChatGPT接続
- Prompt、Resource、利用ガイドの拡充
- Toolの検索性、監査ログ、Token管理画面
- SAP S/4HANA連携およびAccountaがMCP Clientになる構成
