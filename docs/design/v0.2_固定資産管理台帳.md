# Accounta v0.2 固定資産管理台帳 詳細設計書

この文書は、[Accounta要求仕様書](../../SPEC.md)のv0.2で追加する固定資産管理台帳の詳細設計を定義する。

v0.1の機能、権限、Organization単位のデータ分離およびExcel出力は維持し、固定資産管理に必要な変更だけを追加する。実装時は[Accounta v0.1 実装指示書](v0.1_基本機能.md)と既存コードを優先する。

現行実装を正とする。この文書と実装が異なる場合は実装を優先し、文書を更新する。後続バージョンで追加した仕訳帳、Excel「まとめ」およびダッシュボードP/L等の詳細は[v0.3 仕訳帳と証憑管理](v0.3_仕訳帳と証憑管理.md)を参照する。

---

# 1. 対象範囲

v0.2で実装する機能:

- 固定資産の一覧表示
- 固定資産の詳細表示
- 固定資産の登録、編集および削除
- 償却方法、減価償却額および資産状態の管理
- 取得価額と減価償却累計額から算出する帳簿価額の表示
- Organization単位のデータ分離
- 通常のExcelエクスポートへの固定資産管理台帳Sheet追加
- 固定資産一覧の取得年・資産区分・部門・状態による絞り込み
- 固定資産に関するFeature Test

v0.2では次を実装しない:

- 減価償却費、償却率および耐用年数の自動判定・自動計算
- 月別または年度別の減価償却履歴
- 固定資産の分割、統合、移動および一部売却
- 売却損益、除却損、減損および税務調整の計算
- 固定資産からの仕訳生成
- 証憑ファイルとの紐付け
- 固定資産データのImport
- 資産区分マスタ

# 2. 設計方針

## 2.1 台帳の単位

- 1つの固定資産を1レコードとして保存する
- レコードは固定資産の最新状態を表すスナップショットとする
- 当期減価償却費と減価償却累計額は利用者が計算して入力する
- 会計年度や月ごとの償却履歴は保持しない
- 年度更新処理や当期減価償却費の自動リセットは行わない

## 2.2 帳簿価額

帳簿価額は次の式で算出する。

`帳簿価額 = 取得価額 - 減価償却累計額`

- 帳簿価額はDBへ保存せず、画面表示およびExcel出力時に算出する
- 減価償却累計額には当期減価償却費を含むものとする
- 入力値の整合性を検証し、帳簿価額が残存価額を下回る状態を保存させない
- 売却または除却後も取得価額、減価償却額および帳簿価額を保持する

## 2.3 資産区分

- 資産区分は税務上の減価償却資産区分と企業で一般的な固定資産区分を参考にした固定選択肢とする
- 選択値は表示名ではなく定義済みコードを保存する
- 定義済み区分に該当しない場合は `other` を選択し、その他区分名を入力する
- 資産区分マスタは追加せず、資産区分と予実管理科目は別概念として扱う
- v0.2では固定資産と予実管理科目を関連付けず、仕訳連携時に各固定資産へ仕訳用勘定科目を設定する方式を検討する

## 2.4 部門

- 固定資産は必ず1つの部門に所属する
- 新規登録ではログインユーザーと同じOrganizationに属する有効な部門だけを選択できる
- 編集では、現在選択されている部門が無効であっても表示・維持できる
- 他Organizationの部門は選択、参照および保存できない

# 3. 権限制御

固定資産はマスタではなく業務データとして扱う。

| 操作 | `admin` | `company_admin` | `user` |
| --- | --- | --- | --- |
| 一覧表示 | 可 | 可 | 可 |
| 詳細表示 | 可 | 可 | 可 |
| 登録 | 可 | 可 | 可 |
| 編集 | 可 | 可 | 可 |
| 削除 | 可 | 可 | 可 |
| Excel出力 | 可 | 可 | 可 |

- すべての操作は認証を必須とする
- ユーザー種別にかかわらず、ログインユーザー自身のOrganizationに属する固定資産だけを利用できる
- URLへ他Organizationの固定資産IDを指定した場合は `404 Not Found` とし、存在を開示しない
- リクエストの `organization_id` は受け付けず、ログインユーザーのOrganizationからサーバー側で設定する

# 4. 画面設計

## 4.1 画面一覧

| 画面 | Route名 | 主な用途 |
| --- | --- | --- |
| 固定資産一覧 | `fixed-assets.index` | 所属Organizationの固定資産を確認する |
| 固定資産登録 | `fixed-assets.create` | 固定資産を新規登録する |
| 固定資産詳細 | `fixed-assets.show` | 全登録項目と帳簿価額を確認する |
| 固定資産編集 | `fixed-assets.edit` | 固定資産の最新状態を更新する |

通常ナビゲーションのラベルは「固定資産」、一覧画面の見出しは「固定資産管理台帳」とする。ダッシュボードの固定資産セクション見出しも「固定資産」とし、`held` の固定資産だけを対象とするサマリーカードで保有中固定資産数、取得価額合計および帳簿価額合計を表示する。各カードは固定資産一覧へ遷移する。ダッシュボード全体の構成は[v0.1 実装指示書](v0.1_基本機能.md)のダッシュボード節を正とする。

## 4.2 固定資産一覧

- 1ページ20件でページネーションする
- 資産コード昇順、同一コードの場合はID昇順で表示する
- 取得年、資産区分、部門および状態で絞り込める
- 絞り込み条件はユーザーごとにCacheへ保存し、`reset_filters` で初期化する
- 部門の絞り込み選択肢には無効な部門も含める
- 次の項目を表示する
  - 資産コード
  - 資産名
  - 資産区分
  - 部門コード・部門名
  - 取得価額
  - 減価償却累計額
  - 帳簿価額
  - 状態
- 資産コードは詳細画面へのリンクとする
- 一覧行には編集・削除操作を置かない。編集と削除は詳細画面で行う
- 金額は3桁区切り、小数2桁で表示する
- 削除は詳細画面の確認Modalを経由し、選択した固定資産だけを削除する

## 4.3 固定資産登録・編集

入力項目の表示順:

1. 資産コード
2. 資産名
3. 資産区分
4. その他区分名
5. 部門
6. 取得日
7. 供用開始日
8. 取得価額
9. 耐用年数
10. 償却方法
11. 残存価額
12. 当期減価償却費
13. 減価償却累計額
14. 状態
15. 帳簿価額
16. 備考

- 帳簿価額は入力項目にせず、登録画面では説明文、編集画面では現在値として表示する
- 残存価額、当期減価償却費および減価償却累計額の初期値は `0` とする
- 状態の初期値は `held` とする
- 登録画面の取得日の初期値は当日、償却方法の初期値は `straight_line` とする
- 登録成功後は一覧画面へ遷移し、完了メッセージを表示する
- 更新成功後は詳細画面へ遷移し、完了メッセージを表示する
- 入力エラー時は入力内容とエラーメッセージを保持する

## 4.4 固定資産詳細

- DBに保存した全項目を表示する
- 帳簿価額を取得価額、減価償却累計額と並べて表示する
- 登録日時と更新日時を表示する
- 一覧へ戻る、編集、削除の操作を提供する

## 5.2 制約とIndex

- 主キー: `id`
- 一意制約: `unique(['organization_id', 'asset_code'])`
- 将来のOrganization整合性参照用: `unique(['organization_id', 'id'])`
- 一覧取得用Index: `index(['organization_id', 'status', 'asset_code'])`
- `organization_id` は `organizations.id` を参照し、削除を制限する
- `organization_id` と `department_id` の複合外部キーで、同一Organizationの `departments` だけを参照可能にする
- Departmentが固定資産から参照されている間はDepartmentを物理削除できない

| Code | 表示名 |
| --- | --- |
| `building` | 建物 |
| `building_equipment` | 建物附属設備 |
| `structure` | 構築物 |
| `machinery_equipment` | 機械及び装置 |
| `ship` | 船舶 |
| `aircraft` | 航空機 |

| `tool` | 工具 |
| `furniture_fixture` | 器具及び備品 |
| `software` | ソフトウェア |

`land` と `construction_in_progress` は償却対象外とする。`other` の場合は `asset_category_detail` を必須とする。

## 5.4 償却方法コード

| Code | 表示名 |
| --- | --- |
| `straight_line` | 定額法 |
| `declining_balance_old` | 定率法（旧） |
| `declining_balance_200` | 200%定率法（新定率法） |
| `units_of_production` | 生産高比例法 |
| `sum_of_years_digits` | 級数法 |
| `not_applicable` | 償却対象外 |
| `other` | その他 |

償却方法は選択値だけを保存する。償却率、改定償却率、保証率、総利用可能量等は `notes` へ入力する。

## 5.5 資産状態コード

| Code | 表示名 | 意味 |
| --- | --- | --- |
| `held` | 保有中 | 供用前、使用中または一時休止を含む保有状態 |
| `sold` | 売却 | 売却済み |
| `retired` | 除却 | 除却済み |
| `other` | その他 | 上記以外。内容は備考へ記録する |

v0.2では売却日、除却日および処分価額の専用項目を設けない。

# 6. 入力Validation

## 6.1 単項目Validation

| 項目 | Rule |
| --- | --- |
| 資産コード | 必須、文字列、32文字以内、英大文字・数字・`_`・`-`、先頭は英大文字または数字 |
| 資産名 | 必須、文字列、100文字以内 |
| 資産区分 | 必須、定義済みの資産区分コード |
| その他区分名 | 資産区分が `other` の場合は必須、文字列、100文字以内 |
| 部門 | 必須、整数、同一Organizationに属する選択可能なDepartment |
| 取得日 | 必須、有効な日付、`1900-01-01`から`9999-12-31` |
| 供用開始日 | 任意、有効な日付、`1900-01-01`から`9999-12-31` |
| 取得価額 | 必須、正数、整数13桁・小数2桁以内 |
| 耐用年数 | 任意、整数、1年以上255年以下 |
| 償却方法 | 必須、定義済みの償却方法コード |
| 残存価額 | 必須、0以上、整数13桁・小数2桁以内 |
| 当期減価償却費 | 必須、0以上、整数13桁・小数2桁以内 |
| 減価償却累計額 | 必須、0以上、整数13桁・小数2桁以内 |
| 状態 | 必須、定義済みの資産状態コード |
| 備考 | 任意、文字列、500文字以内 |

## 6.2 相関Validation

- 供用開始日を入力する場合、取得日以後の日付とする
- 残存価額は取得価額以下とする
- 減価償却累計額は `取得価額 - 残存価額` 以下とする
- 当期減価償却費は減価償却累計額以下とする
- 土地と建設仮勘定の償却方法は `not_applicable` とする
- 償却方法が `not_applicable` の場合、当期減価償却費と減価償却累計額は0とする
- 資産コードはOrganization内で一意とし、更新時は編集中のレコードを重複判定から除外する
- 新規登録では有効なDepartmentだけを許可する
- 更新では現在設定されているDepartmentに限り、無効でも維持を許可する

## 6.3 入力正規化

- 資産コードは前後空白を除去して英大文字へ変換する
- 資産名、資産区分、その他区分名および備考は前後空白を除去する
- 空文字のその他区分名、供用開始日、耐用年数および備考はNullとして扱う
- Organization IDと帳簿価額はRequest入力から除外する

`FixedAssetSeeder` は通常の `DatabaseSeeder` から実行し、各Organizationへ再現可能なサンプル固定資産を登録する。

## 7.2 Model Relation

- `Organization::fixedAssets(): HasMany`
- `Department::fixedAssets(): HasMany`
- `FixedAsset::organization(): BelongsTo`
- `FixedAsset::department(): BelongsTo`
- `FixedAsset::scopeForOrganization(Builder $query, int $organizationId): Builder`

`FixedAsset` の日付項目は日付型、金額項目は小数2桁としてCastする。償却方法と状態のコード・表示名はModelの定数配列で管理し、既存Modelの選択肢管理方法に合わせる。

## 7.3 Controller制御

- 一覧、詳細、編集、更新および削除では必ずOrganization Scopeを適用する
- 登録は `$request->user()->organization->fixedAssets()` Relationから行う
- 詳細、編集、更新および削除では、Organization Scope適用後にID検索し、対象外なら404とする
- 登録画面では同一Organizationの有効なDepartmentをコード順に取得する
- 編集画面では有効なDepartmentに加えて現在選択中のDepartmentを取得する
- 削除は物理削除とする
- v0.2では全ユーザー種別の操作権限が同一であるため、固定資産専用Policyは追加しない

| 8 | `AcquisitionCost` | 取得価額 |
| 9 | `UsefulLifeYears` | 耐用年数 |
| 10 | `DepreciationMethod` | 償却方法コード |
| 11 | `ResidualValue` | 残存価額 |
| 12 | `CurrentPeriodDepreciationExpense` | 当期減価償却費 |
| 13 | `AccumulatedDepreciation` | 減価償却累計額 |
| 14 | `BookValue` | 算出した帳簿価額 |
| 15 | `Status` | 資産状態コード |
| 16 | `Notes` | 備考 |

- 資産コード昇順、同一コードの場合はID昇順で出力する
- 日付はExcel日付として出力し、`yyyy-mm-dd` 形式で表示する
- 金額は数値として出力し、3桁区切り・小数2桁で表示する
- 耐用年数は整数として出力する
- 資産コード、名称、区分、部門コード、償却方法、状態および備考は文字列として明示的に出力する
- 文字列が `=`、`+`、`-` または `@` で始まってもExcel数式として評価させない
- 見出しと通常データを確認できる固定列幅を設定する

# 10. 自動テスト設計

## 10.1 CRUD

- 認証済みユーザーが固定資産を登録できる
- 登録時にログインユーザーのOrganization IDがサーバー側で設定される
- 資産コードが正規化される
- 一覧に自Organizationの固定資産だけが表示される
- 一覧から詳細へ遷移でき、詳細画面に全項目と正しい帳簿価額が表示される
- 固定資産を編集できる
- 固定資産を詳細画面から削除できる
- `admin`、`company_admin`、`user` のすべてがCRUDできる
- Guestは固定資産Routeを利用できない

## 10.2 Validation

- 同じOrganization内の資産コード重複を拒否する
- 異なるOrganizationでは同じ資産コードを許可する
- 不正な資産コード、日付、金額、耐用年数、償却方法および状態を拒否する
- 定義外の資産区分を拒否し、`other` ではその他区分名を必須とする
- 土地と建設仮勘定で償却方法が `not_applicable` 以外の場合に拒否する
- 償却対象外の資産へ減価償却額が入力された場合に拒否する
- 供用開始日が取得日より前の場合に拒否する
- 残存価額が取得価額を超える場合に拒否する
- 減価償却累計額が取得価額から残存価額を引いた額を超える場合に拒否する
- 当期減価償却費が減価償却累計額を超える場合に拒否する
- 他OrganizationのDepartment指定を拒否する
- 新規登録で無効なDepartment指定を拒否する
- 編集時に既存の無効なDepartmentを維持できる

## 10.3 Organization分離

- 他Organizationの固定資産を一覧へ表示しない
- 他Organizationの固定資産の詳細、編集、更新および削除は404になる
- リクエストへOrganization IDを含めても所属先を変更できない
- DBの複合外部キーが他OrganizationのDepartment参照を拒否する

## 10.4 Excel

- `固定資産管理台帳` Sheetが定義した順序で追加される
- 固定資産0件でも見出しを出力する
- 自Organizationの固定資産だけを出力する
- 全ユーザー種別のWorkbookに固定資産Sheetを含める
- 見出し、日付形式、金額形式、列幅および並び順が設計どおりである
- 帳簿価額が正しく算出される
- 文字列をExcel数式として評価させない

## 10.5 ダッシュボード・一覧絞り込み

- `held` の固定資産件数だけを表示する
- `held` の取得価額合計と帳簿価額合計を表示する
- 売却、除却、その他状態および他Organizationの固定資産を集計しない
- ダッシュボードに「固定資産管理台帳」という見出しを出さない
- 取得年、資産区分、部門および状態の絞り込みが自Organizationのデータだけに適用される
- 条件に一致する固定資産がない場合の空表示を確認する
